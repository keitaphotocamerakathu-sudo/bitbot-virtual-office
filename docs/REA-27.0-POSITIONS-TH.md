# REA 27.0 — เพิ่มช่องลงทุนเงินจริงเป็น 5

เจ้าของขอเพิ่มสถานะพร้อมกันจาก 2 เป็น 5 ในวันที่ 18 พฤศจิกายน 2569 การเปลี่ยนนี้ใช้กับบัญชีเงินจริงที่อนุมัติเท่านั้น บัญชีอื่นและ Paper ทั้ง 10 พอร์ตยังใช้ค่าเดิม 2 เพื่อเก็บผลเปรียบเทียบต่อเนื่อง

## กฎที่ใช้

- นับเหรียญที่ถือและคำสั่งซื้อสถานะ RESERVED, SUBMITTING, OPEN, PARTIAL, CANCEL_PENDING และ UNKNOWN เป็นช่องที่ใช้อยู่ เหรียญเดียวที่จับคู่บางส่วนกับซื้อค้างนับหนึ่งช่อง
- `rea.live_accounts.max_positions` เป็นค่าจาก Server ช่วง 1–5 ค่าเริ่มต้น 2 ตัว Worker เปลี่ยนค่านี้ผ่าน checkpoint ไม่ได้
- การเปิดซื้อเมื่อเกิน 2 ต้องมี `approval.positionPolicy` ผูกเจ้าของ จำนวนช่อง และรุ่น `REA-POSITIONS-27.0` การเปลี่ยนค่าจริงบันทึกใน audit log
- งบเสี่ยงพื้นฐาน `R` = ปัดลง 2 ตำแหน่งของค่าน้อยสุดระหว่าง 100 บาท กับ 1% ของทุนเริ่มวันและ Equity; โหมดทุนจำกัดไม่เกิน 1% ของทุนที่อนุมัติ
- เมื่อมี `N > 2` ช่อง งบเสี่ยงต่อไม้ใหม่ = ปัดลงของ `R × 2/N` และงบเสี่ยงรวมสถานะกับซื้อค้างไม่เกิน `2 × R` ไม้ใหม่จึงเล็กลง ไม่ขยายวงเงินตามจำนวนช่อง
- ความเสี่ยงแต่ละไม้รวมระยะ Stop ค่าธรรมเนียมไปกลับ 0.50% Slippage 0.20% และสำรองปัดเศษ 0.10 บาท ปัดความเสี่ยงขึ้นเพื่อไม่รายงานต่ำกว่าจริง
- ไม้ที่ถือเดิมไม่ถูกปรับขนาดหรือจุดออก ใช้งบรวมอย่างน้อยตามสัดส่วนแบบจำลองตอนซื้อ หรือความเสี่ยงจาก Stop ปัจจุบันรวมสำรอง แล้วเลือกค่าที่สูงกว่า
- ไม้ใหม่ต้องผ่านงบเสี่ยงรายวัน เงินสด ขั้นต่ำตลาด ราคา สัญญาณ และกฎเดิมทั้งหมด ช่องว่างจึงไม่ได้หมายความว่าจะซื้อทันที
- ทุนที่จัดสรร วงเงินต่อเหรียญ วงเงินถือรวม และขาดทุนรายวัน 3% ใช้ค่าเดิม การเติม Wallet ไม่เพิ่มทุนบอทเอง
- การขายลดความเสี่ยงยังทำงานได้เมื่อวงเงินซื้อใหม่หมด Single Active Executor, lease และ revision fencing ใช้ต่อ

ตัวอย่างทุนที่อนุมัติ 99.97 บาทและ Equity 98.21 บาท: `R = 0.98` บาท, 5 ช่องให้งบไม้ใหม่ไม่เกิน 0.39 บาท, งบรวม 1.96 บาท และเพดานขาดทุนรายวันเดิม 2.99 บาท หากไม้เดิมใช้ความเสี่ยงรวมหมดแล้วจะรอ การขาดทุนจริงอาจเกินแบบจำลองเมื่อราคากระโดดหรือสภาพคล่องไม่พอ

## หน้าจอและทีมตรวจ

Live และ Settings อ่านจำนวนช่องจาก Server แสดงเช่น `2 / 5` พร้อมงบเสี่ยงต่อไม้และงบรวมที่เหลือ คำแนะนำเติมเงินใช้กฎเดียวกับตัววางคำสั่ง ไม่เสนอเติมเพื่อข้ามงบเสี่ยง Portfolio Auditor อ่านเพดานบัญชีจริง Correlation Reviewer ตรวจครบทุกคู่ของเหรียญที่ถือหรือซื้อค้าง สูงสุด 10 คู่เมื่อมี 5 เหรียญ ใช้ข้อมูลชุดเดิม

ไม่ได้เปิดบริการ Codex เพิ่ม และไม่ได้เปลี่ยนกลยุทธ์ซื้อ จุดขาย หรือการทดลองป้องกันกำไรให้ทำงานในเงินจริง

## การติดตั้งและตรวจรับ

1. ใช้ `supabase/rea_live_position_limit_v10.sql` เพิ่มคอลัมน์และด่านตรวจ โดยบัญชีที่มีอยู่ยังเป็น 2
2. ตรวจด้วย `npm test` และ `tests/rea-position-limit-database.sql` ชุด SQL สร้างเจ้าของจำลองและ rollback ทั้งหมด ไม่เรียก Exchange
3. Deploy Backend และหน้าเว็บ ตรวจ Browser flows และมือถือผ่าน workflow
4. เปลี่ยนค่าของบัญชีที่เจ้าของสั่งเป็น 5 เมื่อ executor ว่าง ใน transaction เดียวกัน: คอลัมน์, `state.maxPositions`, `approval.positionPolicy`, revision และ audit log เก็บเงิน ทุกรายการซื้อขาย จุดออก และสถานะล็อกเดิมไว้
5. ตรวจรอบ Strategy และ risk watchdog หลังเปลี่ยนค่า ห้ามสั่งซื้อขายจริงเพื่อทดสอบจำนวนช่อง

ทดสอบเพิ่มเติมครอบคลุมช่องที่ 6, pending/partial/unknown, งบต่อไม้และงบรวม, การปลอมสิทธิ์/จำนวนช่องจาก Worker, revision เก่า, executor ซ้ำ, daily lock, การส่งซ้ำ และการขายลดความเสี่ยงเมื่อวงเงินเต็ม
