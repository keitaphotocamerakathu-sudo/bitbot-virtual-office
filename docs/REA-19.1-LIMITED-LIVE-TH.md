# REA 19.1 — เปิด Live วงเงินจำกัด

หน้า `rea.html#live` ส่งคำขอเปิดเงินจริงผ่าน JWT ของเจ้าของบัญชี ระบบใช้ API Key จาก Vault และผลจับคู่จาก Bitkub เท่านั้น ค่าเริ่มต้นของบัญชียังเป็น `LIVE_LOCKED` จนเจ้าของยืนยันบนเว็บ ไม่มีคำสั่งซื้อจากการโหลดหน้า การบันทึก Key หรือการติดตั้งรุ่นนี้

## เปิดด้วยยอด 99.97 บาท

เลือก “เงินจริงวงเงินจำกัด ไม่เกิน 100 บาท” วงเงินเริ่มต้นอ่านจาก THB ที่ใช้ได้จริง (สูงสุด 100 บาท) ยืนยันความเสี่ยง สิทธิ์ Trade/ปิด Withdraw และรับทราบผลตรวจรับเต็มที่ยังไม่ครบ จากนั้นพิมพ์ `เปิดซื้อขายจริง Bitkub` และกดเปิด Live Trading จริง

การเปิดวงเงินจำกัดอนุญาตเงินจริงก่อนครบการตรวจรับเต็ม โดยบันทึกการยอมรับพร้อมเจ้าของ วงเงิน นโยบาย และ fingerprint ของ API Key ที่เซิร์ฟเวอร์ ไม่เปลี่ยนผลตรวจรับที่ยังไม่ผ่านเป็นผ่าน ไม่อ้างว่า Paper ครบ 7 วัน หรือผ่าน formal review/การแจ้งเตือนภายนอกแล้ว

| ข้อจำกัด | ทุน 99.97 บาท |
|---|---:|
| ความเสี่ยงตามแบบจำลองต่อรายการ | สูงสุด 0.99 บาท |
| ขาดทุนรายวันแล้วล็อกการซื้อ | 2.99 บาท |
| ต้นทุนต่อเหรียญรวมซื้อค้าง | สูงสุด 39.98 บาท |
| ต้นทุนรวมและซื้อค้าง | สูงสุด 79.97 บาท |
| จำนวนเหรียญรวมซื้อค้าง | สูงสุด 2 |

วงเงินเสี่ยงปัดลงเป็นสตางค์ กำไรไม่เพิ่มเพดานวงเงินที่อนุมัติอัตโนมัติ ขนาดคำสั่งยังต้องผ่านขั้นต่ำและความละเอียดราคาของแต่ละตลาด หากไม่พอขั้นต่ำหรือไม่มีสัญญาณครบ บอทรอและแสดงเหตุผล Stop Loss อาจขาดทุนเกินแบบจำลองเมื่อราคากระโดด

## การตรวจที่ยังบังคับใช้

- Private API/Wallet สด, ตัวส่งเดิมหยุด, independent watchdog สด และผลทดสอบ execution/recovery/limited capital
- การยืนยันวงเงินเกิดที่เซิร์ฟเวอร์ `rea_live_control` สิทธิ์ service role เท่านั้น
- `rea_live_dispatch` ตรวจเจ้าของการอนุมัติ นโยบาย วงเงินที่เปลี่ยนไม่ได้ fingerprint Key, lease/revision, คำสั่งและ body/path ที่ตรงกัน ราคา/Wallet สด วงเงินเสี่ยง ต่อเหรียญ และ exposure ก่อนบันทึก SUBMITTING และส่ง
- Unknown/partial/cancel/restart ใช้กลไกกระทบยอดเดิม ไม่ส่งซื้อซ้ำจากการ retry ไม่มี endpoint ถอนเงิน
- รูปแบบ STANDARD ต้องผ่านการตรวจรับเต็มก่อนเปิด และไม่ถูกปลดล็อกด้วยการยอมรับวงเงินจำกัด

## ตรวจสอบ

`npm test` และ browser flows ใน CI รวมถึงการเปิดวงเงิน 99.97, การยอมรับครบ, ทุนเกิน Wallet/เกิน 100, การสลับบัญชี และปุ่มหน้าเดิมไปหน้า Live

`tests/rea-live-database.sql` และ `tests/rea-limited-live-database.sql` ตรวจ transaction/dispatch/วงเงิน/การยืนยันและการป้องกันซ้ำกับ PostgreSQL จริง ทุก fixture อยู่ใน transaction ที่ rollback และไม่เรียก HTTP ซื้อขาย

ไฟล์ `supabase/rea_limited_live_v4.sql` อัปเกรดเฉพาะฟังก์ชันเดิม ไม่เปิดบัญชี Live หรือส่งคำสั่งซื้อ ผล `LIMITED_CAPITAL_TESTS` บันทึกผ่านหลังตรวจชุดทดสอบสำเร็จจริงเท่านั้น
