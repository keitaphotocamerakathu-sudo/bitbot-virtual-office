# REA 31.0 · กลยุทธ์หลายระยะและการตรวจหลักฐาน

รุ่นนี้เพิ่มพอร์ต Paper ใหม่ 1 พอร์ต ทุนจำลอง 10,000 บาท ใช้วงเงินร่วมกันทุกกลยุทธ์ พร้อม Dashboard `/rea.html#strategies` การตั้งค่าและประวัติแยกจากพอร์ตเงินจริง ระบบเดิมและ Paper 10 ชุดเก็บประวัติต่อ ไม่มีการเปลี่ยนสิทธิ์ Live งบเงินจริง จุด Stop หรือวิธีจัดการสถานะจริงจากผลทดลองนี้

## สิ่งที่พัฒนาและตรวจสอบ

| ส่วน | การทำงาน |
|---|---|
| Market Intelligence | ค้นตลาด THB ที่เปิดซื้อขาย ตรวจราคา/Depth อายุไม่เกิน 30 วินาที, Spread, Volume, ราคาผิดปกติ และ 6 ภาวะตลาด |
| Technical Analysis | แท่งปิด 1/5/15 นาที, 1/4 ชั่วโมง, วันและสัปดาห์; Wilder RSI/ADX/ATR, MACD, EMA/SMA, Bollinger, VWAP, OBV, แนวรับต้าน, Fibonacci, Volume และรูปแบบแท่ง |
| Entry & Exit | 7 กลยุทธ์รุ่นคงที่ มีกรอบยืนยัน จุดเข้า Stop เป้าหมาย ระยะถือและเหตุผล BUY/SELL/WAIT |
| Risk Management | ทุนอ้างอิง, เสี่ยงไม่เกิน 1%/ไม้, 5 ช่องรวมซื้อค้าง, เสี่ยงเปิดรวมไม่เกิน 3%, ขาดทุนรายวันไม่เกิน 3%, สำรองเงินสด 30%, Exposure 70%, Correlation, Drawdown และพักหลังขาดทุน |
| Backtesting | ข้อมูล Bitkub จริง 4 เหรียญ 120 วัน พร้อมช่วงเตรียมอินดิเคเตอร์, 144 แบบจำลองแบ่งตามเวลา, ทุน 100/10,000 บาท, ต้นทุนฐาน/สูง, Buy & Hold และ Monte Carlo เมื่อจำนวนรายการพอ |
| News & Sentiment | ตรวจ HTTPS/เจ้าของโดเมน/วันที่/ข่าวซ้ำ/เนื้อหาที่อ่านได้, ข่าวโครงการ/Exchange/ความปลอดภัย/อัตราดอกเบี้ย/เงินเฟ้อ; ข่าวลือไม่อนุมัติซื้อ |
| Smart Execution & Learning | จำลองจาก Depth ที่สังเกตภายหลัง, จำกัดปริมาณจับคู่, Partial Fill, Timeout, Stop Gap, บันทึกค่าธรรมเนียม/Slippage/เวลารอ, สมุดบทเรียนและผลสุทธิ |

ความสามารถขั้นสูง 8 ส่วนประกอบด้วยการแยกภาวะตลาด จัดอันดับเหรียญ เลือกกลยุทธ์รุ่นคงที่ จัดการจุดออก คุมความเสี่ยงพอร์ต วัดคุณภาพคำสั่ง ตรวจหลักฐานกลยุทธ์ และวิเคราะห์เหตุผลที่รอ/ข้อมูลผิดปกติ ไม่มี LLM อนุมัติวงเงินหรือสร้างกฎแล้วเปิดใช้ Live

กลยุทธ์: Trend, Breakout, Mean Reversion และ Momentum ระยะสั้น; Pullback และ Swing ระยะกลาง; Position ระยะยาว การเปลี่ยนการตั้งค่ามีผลกับแผนใหม่ ระยะถือและวิธีออกถูกบันทึกตอนเข้า ไม่เปลี่ยนไม้สั้นที่ขาดทุนให้เป็นไม้ยาว จุด Stop เลื่อนขึ้นได้ตามกฎแต่ไม่ขยายลงเพื่อหลีกเลี่ยงการตัดขาดทุน

## การทำงานจริงบน Backend

Supabase Edge Function `bitbot-v10` ใช้ตัวจัดตาราง Paper เดิมทุกนาที การโหลดข้อมูลเสริมอยู่เฉพาะฝั่ง Paper และนอกทางส่งคำสั่งเงินจริง ระบบเฝ้าความเสี่ยงเงินจริงเดิมแยกทุก 15 วินาที พอร์ตใหม่ไม่ได้อ้างว่ามีการป้องกันระดับมิลลิวินาที

Docker รองรับรหัสเดียวกันและผ่านการนำเข้าโมดูล/Transport/Compose ใน CI การมีไฟล์ Docker ไม่ได้หมายความว่าได้เช่า VPS หรือย้ายงานไป Container Host แล้ว

พอร์ตใหม่ใช้ lease และ revision ของ Paper parent พร้อม config revision และบันทึก parent, Paper เดิม, Master, journal และ equity ในธุรกรรมเดียว สถานะหลายช่วงเวลาระหว่างโหลดข้อมูลมี clock ของตนเอง Server ตรวจช่วงเวลาและราคาใหม่ การตั้งค่าใหม่ทำให้ worker รุ่นเก่าสูญเสียสิทธิ์บันทึก

## ฐานข้อมูลและความปลอดภัย

Migration `supabase/rea_master_v14.sql` เพิ่มเฉพาะ `rea.master_books`, `master_journal`, `master_equity`, `master_strategy_versions` และ RPC ของ Master ใช้ RLS และปิดสิทธิ์ anon/authenticated; Dashboard อ่านผ่าน JWT ที่ตรวจเจ้าของฝั่ง Server เท่านั้น

RPC ตรวจ Paper protocol, เพดาน 5 ช่อง, horizon/version ที่ล็อก, เวลา quote/depth, ต้นทุนสุทธิและความเสี่ยงจาก ledger อีกครั้ง ไม่เชื่อค่า summary ที่ Client ส่งมา การทดสอบ SQL ใช้บัญชีสังเคราะห์และ ROLLBACK ทั้งหมด ไม่มี Private Exchange API

ไม่เพิ่ม Secret ลง Source/Browser/ฐานข้อมูล Plain Text และไม่เพิ่มสิทธิ์ถอน การเปลี่ยนค่า Paper เก็บก่อน/หลังใน Audit และ Journal ไม่ผูกกับการเปิด Live

## ผลย้อนหลังที่ตรวจได้

การเปรียบเทียบนอกช่วงพัฒนา 3 ช่วง ช่วงละ 20 วัน ใช้ทุนใหม่แยกในแต่ละช่วง:

| แบบจำลองทุน 10,000 บาท ต้นทุนฐาน | สุทธิรวมสามช่วง | ปิดแล้ว | Profit Factor |
|---|---:|---:|---:|
| รวมกลยุทธ์ จุดออกคงที่ | -341.84 บาท | 4 | 0 |
| รวมกลยุทธ์ จัดการจุดออก | -338.15 บาท | 5 | 0 |
| Pullback ระยะกลาง | -54.05 บาท | 1 | 0 |
| Momentum ระยะสั้น | -145.94 บาท | 2 | 0 |
| Swing ระยะกลาง | -141.75 บาท | 2 | 0 |

แบบอื่นไม่มีรายการปิด จึงใช้พิสูจน์กำไรไม่ได้ **ไม่มีชุดผ่านเกณฑ์** จำนวนตัวอย่างยังน้อยและความครอบคลุมบางช่วงประมาณ 80% ต่ำกว่าเกณฑ์ 90% ไม่ใช้ผลนี้อนุมัติ Live

ตัวเลขข้างต้นเป็นแบบจำลอง OHLC หลังหักต้นทุน ไม่ใช่รายการจับคู่ Exchange และไม่ใช่การลงทุนต่อเนื่องด้วยทุนชุดเดียวสามช่วง ข่าวย้อนหลัง Depth คิวและ Partial Fill ย้อนหลังไม่มี ข้อมูลแท่งที่ซ้ำขัดแย้งกันถูกกักออก ไม่เลือกแท่งที่ทำให้ผลสวยและไม่เติมแท่งปลอม

เลือก BTC/ETH/XRP/ADA ที่อยู่รอดในปัจจุบันและใช้ precision ปัจจุบัน จึงมี survivorship bias และข้อจำกัด metadata กฎออกแบบย้อนหลังโดยทราบปัญหาเดิมแล้ว การแบ่งตามเวลาครั้งนี้เป็น fixed-parameter chronological evaluation ไม่มีการ fit พารามิเตอร์ใหม่แต่ละช่วง จึงไม่อ้างว่าเป็น blind holdout หรือเป็นหลักฐานอิสระในอนาคต ระยะทดสอบ 20 วันไม่เพียงพอยืนยันการถือยาว 180 วัน

ไฟล์หลักฐาน `assets/master-research-v31.json` มีผล 144 scenarios, coverage, ต้นทุน, metrics, Buy & Hold, Monte Carlo แบบ resampling เมื่อมี 30 รายการ, source hashes และข้อจำกัดทั้งหมด Dataset สาธารณะที่ใช้จริงเก็บใน `research/data-v31.json.gz` ตรวจ digest และทำซ้ำได้:

```bash
node research/verify-master-v31.mjs
node research/reproduce-master-v31.mjs
```

## Dashboard และการตั้งค่า

เปิดเมนู **กลยุทธ์สั้น · กลาง · ยาว** เพื่อดู Equity/เงินสด/P&L/ค่าธรรมเนียม/ความเสี่ยงรวม เหตุผลที่รอ ความพร้อมกรอบเวลา ค่าอินดิเคเตอร์ สถานะทีม 7 หน้าที่ แผนซื้อขาย จุดเข้า/ออก เงินต่อไม้ และประวัติจับคู่จำลอง

รายงานแยกสั้น กลาง ยาว รายกลยุทธ์ และรายวัน/สัปดาห์/เดือน กำไรที่ปิดแล้วแยกจากมูลค่าที่ยังถือ “ความครบเงื่อนไข” ไม่ใช่ความน่าจะเป็นชนะ ผลตอบแทนคาดหวังยังเป็น null จนมีข้อมูลอนาคตพอ Profit Factor/Sharpe/Sortino ที่ข้อมูลไม่พอแสดงขีด

ตั้งค่า Risk per Trade, ช่อง, Daily Loss, Portfolio Risk, เงินสดสำรอง, Exposure, Drawdown, Volume, Spread, Net R:R, กลยุทธ์, Timeframe, ระยะถือ, แจ้งเตือนในระบบ และ Pause/Resume/Stop การบันทึกต้องผ่าน Server validation; การชน revision ต้องอ่านใหม่ ไม่เขียนทับเงียบ ๆ

Virtual Office ใช้ผลบันทึก Backend จริง งานเก่าแสดงว่าเก่า ไม่มีการสร้างกิจกรรมเพื่ออ้างว่า AI ทำงาน การหยุด Animation ไม่หยุดบอท ออกจากระบบล้างข้อมูลเจ้าของบนหน้าจอทันที

พอร์ตเงินจริงเพิ่มเพียงข้อสังเกตแบบอ่านอย่างเดียว เช่น มูลค่าถือไม่ถึงขั้นต่ำขาย หรือคำสั่งเดิมยังรอยืนยัน ไม่เพิ่มเหรียญถัวเฉลี่ย ไม่เติมเงิน ไม่เปลี่ยน Stop และไม่ส่งคำสั่งเพราะข้อความวิเคราะห์นี้

## สิ่งที่ยังต้องเก็บหลักฐาน

- **Not Fully Tested:** Paper ใหม่อย่างน้อย 7 วัน, จำนวนขั้นต่ำต่อกลยุทธ์, ความครอบคลุม 90%, การทำงานต่อเนื่องระยะยาว และการถือจริงหลายเดือนยังไม่ครบ
- **Blocked:** ยังไม่มี edge ผ่านเกณฑ์, ยังไม่มี Container Host/VPS ใหม่หรือการส่งแจ้งเตือนภายนอกที่ทดสอบถึงเจ้าของ, การใช้ Codex แบบเสียเงินยังพักตามความต้องการเดิม
- **Not Started:** เปิดใช้กลยุทธ์ใหม่กับเงินจริง, เพิ่มทุนจริงหรือเปลี่ยนการจัดการสถานะจริง ต้องมีหลักฐานและเจ้าของอนุมัติแยก
- Security review อิสระและการตรวจสิทธิ์ API Key ว่าไม่มีถอนยังต้องตรวจรับตามเกณฑ์เดิม การทดสอบอัตโนมัติไม่ได้แทนการตรวจรับทั้งหมด

การตั้ง Paper ใหม่ไม่ใช่การยืนยันว่าระบบพร้อมทำกำไร ขาดทุนจาก gap, สภาพคล่องหรือการหยุดบริการอาจเกินประมาณการ Stop ได้ ระบบวัดความถูกต้องและหลักฐานโดยไม่รับประกันกำไร

### 31.0.1 · ตรวจซ่อมข้อมูลรายวันจากหลักฐาน

ข้อมูลรายวัน API มีบางแท่งเวลาซ้ำแต่ OHLC ไม่ตรงกัน รุ่นนี้กักทั้งสองแท่งแล้วตรวจซ่อมจากรายชั่วโมงจริงครบ 24 แท่งเท่านั้น มี source/evidence/recovered-day ในผลวิเคราะห์ หากยืนยันไม่ได้ยังเว้นช่องข้อมูลและปฏิเสธกลยุทธ์ที่ต้องใช้ความต่อเนื่อง ไม่เปลี่ยนข้อมูลหรือกฎของ Live เดิม กรอบ 1 นาทีใช้ตัวตรวจ trade evidence เดิมเพื่อยืนยันช่วงไม่มีการซื้อขาย ผลย้อนหลังเดิมยังคงกักแท่งที่ขัดแย้ง ไม่อ้างว่าได้ซ่อมย้อนหลังหรือพิสูจน์ผลใหม่แล้ว

สมุด FILL ใหม่บันทึก positionId และแยก Gross P&L, Net P&L, ค่าธรรมเนียมเข้า/ออกและส่วนต่างปัดเศษ ฝั่ง Server คำนวณ Gross จากต้นทุนต่อหน่วยของ entry fills ในประวัติถาวร ไม่อาศัยเฉพาะ 200 fills ล่าสุด หากไม่มีหลักฐานต้นทุนแสดง null พร้อมเหตุผล ไม่เดาตัวเลข รายกลยุทธ์รวม Profit Factor และค่าธรรมเนียมจากประวัติครบ
