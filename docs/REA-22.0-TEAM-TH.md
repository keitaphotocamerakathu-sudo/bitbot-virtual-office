# REA 22.0 — ทีมตรวจสอบ 14 หน้าที่

วันที่ 18 พฤศจิกายน 2569 เพิ่มตัวตรวจเชิงตัวเลข 7 หน้าที่บน Backend รวมกับ 7 หน้าที่เดิมเป็น 14 หน้าที่ ตัวตรวจใหม่ทำงานอัตโนมัติในรอบ Strategy ของเงินจริงและ Paper ใช้ Snapshot ร่วมกัน ไม่เพิ่มการเรียก Codex หรือ LLM และไม่ปรับการตั้งค่า Codex ตามคำขอเจ้าของที่ยังไม่ได้เติมเงิน

## งานที่เพิ่ม

| หน้าที่ | ผลตรวจที่บันทึกจริง |
|---|---|
| Data Integrity Auditor | รูปแบบ OHLCV, แท่งปิด, ช่องว่าง/ซ้ำใน 50 แท่งล่าสุด, จำนวนใน Order Book และราคาเบี่ยงจากแท่งล่าสุด 10 เท่า |
| Liquidity Reviewer | Spread และมูลค่า THB ฝั่งขายภายในกรอบราคาที่อนุญาต |
| Multi-timeframe Analyst | เปรียบเทียบ 5/15 นาทีและ 1 ชั่วโมงจากการรวมแท่งปิดจริง ข้อมูลไม่พอแสดง `INSUFFICIENT` |
| Signal Challenger | ตรวจชุดสัญญาณและบันทึกเหตุผลคัดค้านด้วยกฎเดียวกับเครื่องยนต์เชิงตัวเลข |
| Cost & Exit Reviewer | ประมาณค่าธรรมเนียมไปกลับ Slippage ระยะ Stop และอัตราส่วนผลตอบแทนต่อความเสี่ยงตามแบบจำลอง |
| Portfolio Auditor | สถานะและคำสั่งซื้อค้าง รวม `UNKNOWN` / `CANCEL_PENDING`, ช่องที่ใช้, Exposure และเงินที่อ่านได้ |
| Performance Monitor | เวลาสแกน เวลา Private Preflight เวลากระทบยอด เวลาถึงการตรวจแผน และจำนวนครั้งอ่าน Wallet |

Data Integrity จะตั้ง `dataQuality.ready=false` เฉพาะคู่ที่ข้อมูลผิดรูปแบบ เพื่อให้กฎเดิมปฏิเสธการซื้อใหม่ การขาย Stop Loss ยังคงอาศัยราคาสดและทำงานใน Independent Risk Worker ที่ไม่เรียกทีมวิเคราะห์ ข่าว หรือ Codex ตัวตรวจอื่นบันทึกข้อสังเกต ไม่เพิ่มข้อบังคับให้ทุกตัวโหวตตรงกันก่อนซื้อ

ตัวตรวจใหม่เป็นโมดูลกฎที่ตรวจสอบในโค้ดได้ ไม่ใช่โมเดล AI เพิ่มอีก 7 ตัว ไม่มีข้ออ้างว่าจำนวนหน้าที่ทำให้ Win Rate หรือกำไรสูงขึ้น ต้องประเมินความแม่นยำจากผลที่กระทบยอดจริงต่อไป

## การลดเวลารอ

- อ่าน Wallet และ Open Orders พร้อมกันภายใต้ Executor Lease เดิม โดยรอผลทั้งสองและตรวจข้อผิดพลาดทุกผล
- บัญชีที่ไม่มีคำสั่งค้างใช้ Wallet จาก Preflight ได้เมื่ออายุไม่เกิน 5 วินาที หากมีคำสั่งค้างแม้ไม่เกิด Fill, เวลาอ่านเก่า/ผิดปกติ หรือไม่มี Timestamp ต้องอ่าน Wallet ซ้ำหลังการกระทบยอด
- ใช้ข้อมูลตลาดชุดเดียวกับ Strategy ไม่เพิ่มคำขอข่าว แท่งราคา หรือ Order Book และไม่เปลี่ยนลำดับ/รอบทำงานของ Codex
- `team.timings.pipelineMs` เป็นเวลาตั้งแต่เริ่มรอบถึงก่อนทีมตรวจแผน ไม่ใช่เวลาส่งคำสั่งหรือเวลา Fill ส่วน `latest.performance.pipelineMs` รวมการวางแผนก่อน Checkpoint ไม่ใช่เวลารอบเต็มที่ Exchange

ข้อมูลอ้างอิงก่อนปรับจาก Supabase Function Logs: 18 พฤศจิกายน 2569 เวลา 10:00–11:05 น. Asia/Bangkok เฉพาะ HTTP 200 ไม่ใช้เวลาของ Cron enqueue แทนเวลาประมวลผล

| งาน | จำนวนตัวอย่าง | Median | P95 |
|---|---:|---:|---:|
| `rea-live-risk` | 259 | 1,354 ms | 2,201.5 ms |
| `rea-live-run` | 65 | 4,298 ms | 6,573 ms |

ค่าก่อนปรับนี้เป็นข้อมูลเชิงสังเกต เวลา Exchange และเครือข่ายเปลี่ยนได้ ต้องใช้ช่วงตัวอย่างหลังปรับและจำนวนตัวอย่างกำกับก่อนสรุปว่าระบบเร็วขึ้นจริง

## หน้าเว็บและหลักฐานย้อนหลัง

หน้า [ทีมงาน](https://keitaphotocamerakathu-sudo.github.io/bitbot-virtual-office/rea.html#agents) แสดง 14 หน้าที่ในออฟฟิศ ใช้ Worker ID และ Task ID แยกกัน พร้อมสถานะจากบันทึกจริง ข้อมูลไม่พอแสดงรอ ข้อมูลเก่าแสดงเก่า และแยกแหล่งข้อมูลเงินจริง/Paper

เพิ่ม `rea.review_cycles` เก็บผลทีมตาม `(user_id, mode, at_ms)` แบบเพิ่มรายการอย่างเดียวสำหรับ Backend มี RLS ปิดการอ่าน/เขียนจาก `anon` และ `authenticated` Trigger บันทึกเฉพาะ Receipt ที่เปลี่ยนจาก Strategy และไม่สร้างรายการซ้ำจาก Risk Heartbeat หรือ Retry ข้อมูลผิดรูปแบบ/เกิน 64 KiB ถูกข้ามเพื่อไม่ขวาง Risk Checkpoint โดยไม่แก้ตารางคำสั่ง เงินทุน หรือนโยบายส่งคำสั่ง

การติดตั้งฐานข้อมูล: `supabase/rea_review_team_v6.sql` การทดสอบจริงด้วย `service_role`: `tests/rea-review-database.sql` สร้างบัญชีสังเคราะห์และ Rollback ทั้งหมด ไม่เรียก HTTP หรือ Exchange ทดสอบการแยกโหมด การไม่ซ้ำ ประวัติไม่ถูกแทนที่ สิทธิ์แบบเพิ่มรายการ และข้อมูลเสียไม่ขวาง Checkpoint ผ่านแล้ว

## การตรวจสอบรุ่นนี้

- Backend 260 การทดสอบผ่าน รวมการอ่าน Private API พร้อมกัน การใช้ Wallet สด/บังคับอ่านซ้ำ การปฏิเสธข้อมูลเสียโดยยังขาย Stop Loss ได้ กรอบเวลาที่ข้อมูลไม่พอ และ 14 Worker/Task ID ไม่ซ้ำ
- เพิ่ม Browser Scenario สำหรับผลตรวจ เวลา สถานะเก่า การสลับเงินจริง/Paper และการล้างข้อมูลเมื่อลงชื่อออก ให้ CI ร่วมกับการตรวจมือถือ ออฟฟิศ และ Container เดิม
- Supabase Security Advisor หลังเพิ่มตารางไม่มี Finding ใหม่จากตาราง/Trigger นี้
- ไม่เพิ่มวงเงิน ไม่เพิ่มจำนวนสถานะสูงสุด ไม่เพิ่มการซื้อถัว และไม่ส่งคำสั่งเงินจริงเพื่อทดสอบ
