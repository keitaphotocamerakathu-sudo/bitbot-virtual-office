# Owner-controlled live start — v14.1

The owner requested the ability to buy with real funds without waiting for the research gate. The 14-day/20-round research progress remains factual and unchanged, but is now a research assessment rather than an unavoidable wait when the owner explicitly accepts an unvalidated strategy.

In **เงินจริง → เริ่มบอทเงินจริง**, the existing confirmation shows the configured capital, reserves, order/day limits and exits. If research is incomplete, an unchecked acknowledgement permits starting before research completes. The original risk acknowledgement, withdrawal-disabled acknowledgement and exact typed start phrase remain required. Opening the dialog does not start anything. The start endpoint validates the actual wallet before calling the atomic start RPC. API keys already stored do not need to be entered again for this change.

The server binds that consent to the saved risk configuration. It is valid only while the bot is running, with the same configuration, and is cleared on explicit stop or settings save. Entry pause/resume does not revoke it, but the pause flag still independently blocks new buys. An error stop invalidates it by stopping the bot; the next start needs a fresh acknowledgement. A different capital, strategy or risk setting cannot reuse prior consent. Configuration changes racing a start are rejected by the database's expected-config check and row/advisory locks.

Both company preflight and the final buy gate use this permission. The research result stays `researchPassed=false` and the archive states `ownerApproved=true` instead of pretending that a strategy passed. Orders still need a valid signal, fresh quotes/depth/news, sufficient wallet funds after reserves, market minimums, hourly context, the existing risk limits, an atomic order reservation and exchange reconciliation. Consent never forces a buy, changes limits, fabricates profits, retries unknown orders, or grants withdrawal capability.

Deploy `supabase/bitbot_v15.sql` before the v14.1 Edge Function and web assets. The migration adds a private bot column and service-only atomic start RPC; it neither consents nor starts any account. Server tests and browser tests use mocks for real-start paths. Production state is inspected read-only, and database start/lock behavior is tested inside a rolled-back transaction. No production real start or exchange submission is used as a deployment test.
