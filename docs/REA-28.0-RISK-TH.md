# REA 28.0 — Risk Manager ปกป้องทุน

เจ้าของขอปรับ Risk Manager และแจ้งว่าต้องการกำไรแน่นอน ข้อมูลที่ตรวจเมื่อ 18 พฤศจิกายน 2569 เวลา 23:47 น. ปิดแล้ว 3 ไม้ เป็นขาดทุนรวม 1.85 บาท ยังถือ XRP และยังไม่มีหลักฐานเพียงพอว่ากลยุทธ์ทำกำไรสุทธิได้ ระบบจึงพักซื้อใหม่ผ่าน control เดิม โดยยังเฝ้าจุดขายของไม้ที่ถืออยู่ ไม่รับประกันกำไรหรือชดเชยผลขาดทุนให้หายไป

## กฎที่ใช้กับบัญชีที่อนุมัติ

โปรไฟล์ `CAPITAL_GUARD_28` ผูกกับ `approval.riskPolicy` ฝั่ง Server ค่าเริ่มต้นของบัญชีอื่นยังเป็นกฎเดิม การติดตั้งโค้ดไม่เปิดโปรไฟล์ให้บัญชีอื่น

| กฎ | การทำงาน |
|---|---|
| ฐานทุน | ค่าน้อยสุดของทุนที่อนุมัติ ทุนเริ่มวัน Equity และ 10,000 บาท ไม่ใช้เงินนอกวงเงินมาขยายความเสี่ยง |
| งบเสี่ยงปกติ | ใช้กรอบ REA 27: 1% ของฐานทุนสูงสุด 100 บาท แล้วแบ่งตามจำนวนช่อง โดย 5 ช่องใช้ 2/5 ของงบต่อไม้และรวมไม่เกินงบเดิม 2 ไม้ |
| ขาดทุนรายวันถึง 1.5% | ลดงบต่อไม้และงบเสี่ยงรวมครึ่งหนึ่ง ปัดลง 2 ตำแหน่ง เมื่อหลุดเงื่อนไขนี้ยังต้องตรวจล็อกและเงื่อนไขอื่นใหม่ |
| แพ้ต่อเนื่อง 3 ไม้ | ใช้รายการปิดจริงใน 24 ชั่วโมง พักซื้อ 60 นาทีจากรายการปิดล่าสุด กำไรหรือเท่าทุนตัดลำดับแพ้ |
| ข้ามวัน | เวลา cooldown ยังใช้ต่อ ไม่ปลดเพียงเพราะเปลี่ยนวัน |
| เงินสด | กันสำรอง 30% ของฐานทุน คำนวณหลังหักซื้อค้างและใช้เงินที่ตรวจได้จาก Wallet |
| ต่อเหรียญ / ถือรวม | ไม้ใหม่ไม่เกิน 20% ต่อเหรียญ และถือรวมกับซื้อค้างไม่เกิน 70% ของฐานทุน รวมทั้งต้องไม่เกินเพดานเดิม |
| จำนวนช่อง | สูงสุด 5 รวมคำสั่งซื้อที่ยังไม่สิ้นสุด ไม่บังคับให้ซื้อครบ |
| ขาดทุนรายวัน | คง 3% และการ latch ล็อกเดิม ไม่ปลดเมื่อราคาดีดกลับ |
| ไม้เดิม | ไม่ปรับ Stop/Target หรือต้นทุน ไม่เพิ่มไม้ในเหรียญที่ถืออยู่ งบที่ใช้แล้วอาจเกินกรอบใหม่ได้ จึงห้ามเปิดเพิ่มจนมีที่ว่าง |
| ระหว่างพัก | เฝ้าจุดขายและกระทบยอดต่อ ยกเลิกซื้อค้างที่ขัด cooldown หรือกรอบใหม่ แต่ไม่สั่งขายเพื่อทดสอบ |

ตัวอย่างทุนเริ่มวัน 99.75 บาทและ Equity 97.80 บาท: ขาดทุนวันนี้เกิน 1.5% แล้ว งบต่อไม้ใหม่เหลือประมาณ 0.19 บาท งบเสี่ยงรวมประมาณ 0.96 บาท หากงบไม่รองรับคำสั่งขั้นต่ำ ระบบรอ ไม่ปัดขนาดไม้ขึ้นเพื่อให้ซื้อได้

## ตรวจขั้นต่ำการขายที่ Stop

ก่อนรับไม้ใหม่ ระบบใช้ราคา Limit จำนวนทศนิยมของเหรียญ Stop และขั้นต่ำตลาด คำนวณจำนวนเหรียญหลังสำรองค่าซื้อ 0.25% ปัดขึ้น พร้อมเงินสำรอง 0.10 บาท และมูลค่าขายที่ Stop หลังสำรอง Slippage 0.20% ต้องไม่ต่ำกว่าขั้นต่ำตลาดที่ได้รับมา (อย่างน้อย 10 บาท) โดยใช้มูลค่าก่อนค่าขายตามหน่วยตรวจขั้นต่ำตลาด

แบบจำลองไม่รับประกันว่าจะขายได้ราคา Stop เมื่อราคากระโดด ตลาดถูกพัก หรือจับคู่บางส่วนจนเหลือเศษ ส่วนค่า Fee Credit ที่เกิดจริงบันทึกตามใบจับคู่ ไม่ใช้ส่วนลดที่ยังไม่เกิดมาลดงบเสี่ยงก่อนซื้อ

อ้างอิง [ค่าธรรมเนียม Bitkub](https://support.bitkub.com/en/solutions/articles?id=151000035191), [ขั้นต่ำการซื้อขาย](https://support.bitkub.com/en/solutions/articles?id=KM000009268) และ [API ทางการ](https://github.com/bitkub/bitkub-official-api-docs/blob/master/rest-v3.md) ตรวจวันที่ 18 พฤศจิกายน 2569

## ความสอดคล้องและการตรวจรับ

- ตัววางคำสั่ง ผู้ช่วยทุน และหน้า Live / Settings ใช้กฎชุดเดียวกัน แสดงเหตุผลพัก งบต่อไม้ เงินสำรอง และเวลาพักที่เหลือ
- SQL dispatch คำนวณงบและ cooldown เองอีกครั้ง ตรวจเจ้าของโปรไฟล์ จำนวนช่อง เงินสำรอง ความเสี่ยงรวม และขั้นต่ำมูลค่าขายก่อนอนุญาตส่งจริง
- Worker เปลี่ยนโปรไฟล์หรือลบประวัติปิดขาดทุนเพื่อข้าม cooldown ไม่ได้ ยังคง Single Active Executor, lease, revision และตรวจผลที่ยัง UNKNOWN
- การพักซื้อที่เจ้าของสั่ง (`buyPaused`) คงอยู่จนเจ้าของสั่งทำงานต่อ การครบ cooldown หรือ deploy ไม่ทำให้เปิดซื้อเอง
- ใช้ `npm test`, Browser flows และ `tests/rea-risk-policy-database.sql` ชุด SQL สร้างเจ้าของจำลองและ rollback ทุกอย่าง ไม่เรียก Exchange
- ตั้งโปรไฟล์ให้บัญชีที่เจ้าของอนุมัติเมื่อ executor ว่าง บันทึก audit โดยเก็บทุน ต้นทุน รายการจับคู่ จุดขาย ล็อกรายวันและสถานะพักไว้

Paper ทั้ง 10 พอร์ตยังเก็บผลเดิมต่อ ไม่มีการเปลี่ยนกลยุทธ์เงินจริงให้รับข้อเสนอ Paper โดยอัตโนมัติ ผลอย่างน้อย 7 วัน จำนวนรายการปิดที่เพียงพอ และกำไรสุทธิหลังต้นทุนเป็นข้อมูลสำหรับทบทวน ไม่ใช่หลักประกันกำไร โปรไฟล์นี้เป็นกฎลดความเสี่ยง ยังไม่มีผลทดสอบระยะยาวพิสูจน์ว่าเหมาะที่สุด
